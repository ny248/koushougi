# 広将棋AIの学習

## 対局に使うAI

AIは、局面を採点する1つのNNとαβ探索を組み合わせる。対局画面、自己対戦、モデル間の評価対局は `players.alpha_beta` を通して同じ着手処理を使う。

採点NNは `value_network.ValueNetwork` に置く。線形経路と非線形経路をネットワーク内で合計し、手番側から見た点数を返す。敵側から評価するときは符号を反転する。勝敗が確定した局面は、探索がルールに従って勝敗点を付ける。

初期重みと学習後の重みは同じ計算経路で推論する。出力層の重みがゼロでも、線形経路と非線形経路の両方を計算する。複数局面をまとめる実装でも、同じモデルと同じ入力に対する推論結果の再利用は重みの値によらず共通に行う。

- 線形経路の重みは、従来の駒価値と前進点を正確に再現する値で初期化する。
- 非線形経路は駒状態とマスの特徴を組み合わせる。出力層をゼロで初期化し、途中の層は乱数で初期化する。
- 両方の経路を学習対象にする。学習前の出力は従来評価と一致する。
- 対局時はPython標準ライブラリで重みを評価する。学習時は同じパラメータと計算をPyTorchで扱う。
- 保存形式は `format: 2` のJSON。駒種の並び、ネットワークの幅、全パラメータを含む。

モデルを指定しない場合は初期重みを使う。対局画面の「AI」も初期重みを使う。学習したモデルは自己対戦と評価対局の `--model` または候補モデルの引数で指定できる。

## 学習環境

Python 3.11以降の仮想環境を使い、学習用の依存関係を導入する。

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements-training.txt
mkdir -p work/training
```

Apple Siliconでは `--device mps`、対応するNVIDIA環境では `--device cuda`、CPUでは `--device cpu` を指定する。`auto` はCUDA、MPS、CPUの順に選ぶ。指定したGPUが使えない場合はエラーになる。

## 対局・深い探索・学習・比較を繰り返す

`train_cycle` は世代ごとにNNを固定して対局し、その途中で得た探索評価を教師にする。対局用と教師用に同じ探索を二度行わない。一定手数で収集を区切り、未完了の対局は次の世代へ引き継ぐ。勝敗を待たずに学習できる。

```sh
.venv/bin/python -B -m koushougi.train_cycle \
  --output work/training/cycle-01 \
  --generations 3 --games 6 --chunk-plies 32 --workers 2 \
  --seconds 10 --depth 5 --min-depth 3 \
  --device auto --inference-device auto
```

各世代で6局を32手ずつ進め、そのうち最後の1局を最終確認、もう1局を検証、残りを学習に使う。手数上限や合法手なしによる打ち切りは勝敗に換算しない。探索の上限ではなく、実際に読み切った深さが `--min-depth` 以上の局面だけを教師にする。ルールから勝ちを証明できた探索評価は、浅い深さでも使用する。

開始時にソースと初期モデルを実験ディレクトリへコピーし、固定コードへ切り替える。実行中に作業用のコードを変更しても、その実験には反映されない。`--model` で既存のformat 2モデルから始められる。

### 計算の効率とGPU

- 対局は `--workers` 件まで並行して進める。各プロセスのPyTorchのCPUスレッド数は1にする。
- 探索中のNN評価をまとめ、同じモデルで同じ入力を再評価する計算をキャッシュする。`--inference-batch-size` は既定で128。
- `--inference-device` は探索時の採点に使う装置、`--device` はNNの重みの更新に使う装置。`auto` はCUDA、MPS、CPUの順に選ぶ。`--inference-device native` は従来の標準ライブラリによる推論を使う。
- CPUでの一括推論は倍精度、GPUでは単精度を使う。GPUでは小さな数値差や、それによる同点の手の違いが生じうる。ルールで確定した勝敗はNNより優先する。
- 学習用の入力は装置へ一度まとめて配置する。既定のバッチ数は256、学習率は0.0003、最大40エポック。検証誤差が8エポック改善しなければ止め、検証誤差が最小の重みを保存する。

Apple SiliconでGPUを使う場合は `--device mps --inference-device mps` と明示できる。GPUを検出できないsandbox内では明示指定がエラーになるため、GPUへアクセスできる端末から実行する。実際に選ばれた装置は `process.json` に保存する。

### データと次の世代のモデル

既定では過去4世代の学習局面も再利用する。同一の入力には最新世代の教師値を残す。検証・最終確認の対局群は世代をまたいで固定し、同じNN入力が区分をまたいだ場合は後から現れた区分のデータを除く。最終確認の誤差は学習やエポック選択には使わない。

候補モデルと現在の教師モデルを、異なる序盤4種類で先後を入れ替えて8局比較する。開始局面は学習・検証・最終確認の局面との重複も検査する。既定では決着4局以上、決着した対局で候補の勝率60%以上なら、次の世代の教師へ更新する。`--evaluation-pairs`、`--min-decided`、`--promotion-threshold` で変更できる。この条件は実験内で教師を選ぶ基準であり、統計的な棋力向上の証明ではない。

対局画面へモデルを自動で反映しない。収集・比較の途中経過、打ち切り、読み切った深さ、実際の勝敗を保存する。

### 保存と再開

```sh
.venv/bin/python -B -m koushougi.train_cycle \
  --output work/training/cycle-01 --resume
```

対局は一手ごとの記録から、学習は直近のエポックから再開する。再開時には保存した固定ソースを使い、モデルや学習条件を変更できない。`--device` と `--inference-device` の変更は可能で、CPUとGPUを切り替えた場合の数値の完全一致は保証しない。同一実験の二重起動は実行ロックで防ぐ。

主な成果物は次のとおり。

- `config.json`、`source/`、`initial.json` — 固定した条件・コード・開始モデル。
- `process.json`、`progress.json`、`failure.json` — 実行装置・PID・現在の段階・失敗情報。
- `generation-001/selfplay/` — 一手ごとの盤面、選択した手、探索評価、深さ、乱数状態。
- `generation-001/data-summary.json` — 区分ごとの件数と、深さ不足や重複による除外。
- `generation-001/fit-state.pt` — NN・Adam・乱数・最良の重みを含む学習再開用の保存。
- `generation-001/candidate.json`、`training.json`、`evaluation.json` — 候補モデル、学習結果、比較結果。
- `complete.json` — 全世代の結果。未完了の対局は勝ちや引き分けに換算しない。

## Double DQNによる自己対戦と学習

`train_dqn` は自己対戦を進めながら、経験を保存して繰り返し学習する。対局に使うNNとαβ探索は同じで、学習用に別の対局AIを追加しない。

### Q値と学習目標

広将棋は行動の結果がエンジンで確定するため、Q(s, a)の入力には「局面sで合法手aを指した後の盤面」を使う。NNの形と初期重みは従来の採点NNを引き継ぐ。盤面は次の手番側から符号化されるので、指した側のQ値は `−tanh(NN(行動後の盤面) / 20000)` になる。NN全体の線形経路と非線形経路を更新する。

学習目標は次のとおり。

- その手で勝敗が決まった場合は、指した側の勝ちが+1、負けが−1。次の局面の予測値は足さない。
- 続行中は報酬0とし、相手のすべての合法手を学習用NNで比較する。その最善手を目標値用NNで評価し、目標値を `0 − γ × Q_target(相手の最善手)` とする。手番が相手に移るため符号を反転する。
- 応手で勝敗が確定する場合は、ルールによる±1を使う。射撃、複数段階の移動、任意成り、連動する成りも共通エンジンの合法手を使う。

手数上限で止まった局面は終局にしない。途中の経験も、次の局面の予測値を使って学習できる。合法手がなく勝敗も未定義の局面は、勝ちや引き分けに換算せず、その局面から目標値を作る更新を除外する。

経験の再利用、εによるランダムな探索、目標値用NNは[DQNのPyTorch公式実装](https://docs.pytorch.org/tutorials/intermediate/reinforcement_q_learning.html)を参照する。行動を選ぶNNと、その行動を評価するNNを分ける方式は[Double DQN](https://arxiv.org/abs/1509.06461)を使う。相手の手番で符号を反転する処理と、行動後の盤面によるQ値の表現は、このゲームへの適用である。

### 実行

新しい実験ディレクトリを指定する。次の例では探索確率を20%から2%へ下げ、ランダムに選ぶ場合以外は1手10秒、最大5手先のαβ探索を使う。

```sh
.venv/bin/python -B -m koushougi.train_dqn \
  --output work/training/dqn-01 --games 20 --seed 202 \
  --seconds 10 --depth 5 --device auto
```

学習目標の計算では相手の全合法手を比較する。`--seconds` は着手の探索時間で、NNの更新処理の時間は別にかかる。

| 引数 | 既定値 | 意味 |
| --- | ---: | --- |
| `--gamma` | 0.99 | 一手進むごとの将来の報酬の割引率 |
| `--batch-size` | 16 | 一度の更新に使う経験の件数 |
| `--replay-capacity` | 10000 | 保持する経験の上限。古い経験から置き換える |
| `--warmup` | 64 | 更新開始までにためる経験の件数 |
| `--train-every` | 4 | 何手ごとにNNを更新するか |
| `--learning-rate` | 0.001 | Adamの学習率 |
| `--target-interval` | 1000 | 何回の更新ごとに目標値用NNへ重みをコピーするか |
| `--epsilon-start` | 0.2 | 開始時にランダムな合法手を選ぶ確率 |
| `--epsilon-end` | 0.02 | 探索確率の下限 |
| `--epsilon-steps` | 10000 | 探索確率を下限まで直線的に減らす手数 |
| `--checkpoint-every` | 100 | 何手ごとに再開用ファイルを保存するか。各局の終了時にも保存する |
| `--inference-batch-size` | 256 | 相手の合法手を比較するときにまとめてNNへ渡す件数 |

学習の損失にはHuber損失を使い、勾配のノルムを10で制限する。学習用NNだけを勾配で更新し、目標値用NNには勾配を流さない。

### 保存と再開

実験ディレクトリに次のファイルを保存する。

- `initial.json` — 学習開始時の重み。
- `candidate.json` — 直近に保存した重み。既存の自己対戦・比較処理へそのまま渡せるformat 2。
- `checkpoint.pt` — 学習用NN、目標値用NN、Adamの状態、経験、乱数状態、途中の盤面と手数。
- `config.json` — 保存済みの学習条件。
- `report.json` — 決着した局数、先後の勝ち、打ち切り、更新回数、損失、探索深さ、実行コードのハッシュ。

中断後は同じディレクトリを指定し、最後に保存した状態から再開する。保存後から停止までの計算はやり直す。

```sh
.venv/bin/python -B -m koushougi.train_dqn \
  --output work/training/dqn-01 --resume --device auto
```

再開時は保存済みの条件を使い、異なる条件や実行コードでの再開を拒否する。`--device` は切り替えられる。実行ロックで同じ実験の二重起動を防ぐ。保存は一時ファイルから置き換え、途中停止で未完成のファイルを確定しない。現在のロックはmacOS/Linuxの `fcntl` を使う。

別の実験で追加学習する場合は、新しい出力先と `--model work/training/dqn-01/candidate.json` を指定する。この場合は重みだけを引き継ぎ、経験と最適化状態は新しくする。候補モデルの生成や損失の低下だけでは棋力向上を判断せず、下記のモデル比較を行う。対局画面への採用は別に行う。

## 勝敗と探索評価を教師値とする学習

`selfplay` と `train_value` は、勝敗と探索評価から局面評価を学習する既存の実行経路。DQNの経験や更新とは保存形式が異なるため、DQNを実行するときは上記の `train_dqn` を使う。

初期NNと先読みで対局を生成する。次の例は1手10秒、最大5手先で探索する。

```sh
python3 -m koushougi.selfplay --games 20 --seed 202 \
  --seconds 10 --depth 5 --output work/training/selfplay-01.jsonl
```

勝敗がついた対局の局面をJSONLに保存する。各行には対局番号、手数、手番、盤面、勝敗、探索評価、読み切った深さを含む。手数上限や合法手なしで終了した対局は集計に残し、勝敗付きの学習データには含めない。

```sh
.venv/bin/python -m koushougi.train_value work/training/selfplay-01.jsonl \
  --device mps --output work/training/model-01.json
```

対局単位で約20%を検証用に分ける。少なくとも2局分のデータが必要になる。既定では、手番側から見た最終結果と、探索評価を `tanh(評価値 / 20000)` で変換した値を半分ずつ混ぜて学習する。`--search-weight` で探索評価の比率を0〜1に変更できる。探索評価がない既存の局面データは勝敗を教師値として使う。

`--epochs` は学習回数、`--batch-size` は一度に学習する局面数、`--seed` は対局分割と学習順の乱数を指定する。出力には検証誤差と学習・検証に使った局面数を表示する。

学習したモデルで次の自己対戦を行い、その重みから追加学習できる。

```sh
python3 -m koushougi.selfplay --model work/training/model-01.json \
  --games 20 --seed 203 --seconds 10 --depth 5 --output work/training/selfplay-02.jsonl
.venv/bin/python -m koushougi.train_value work/training/selfplay-02.jsonl \
  --model work/training/model-01.json --device mps --output work/training/model-02.json
```

追加学習は保存した重みから新しい最適化処理を開始する。出力先には新しいファイル名を指定する。

## モデルの比較

同じ探索方法、持ち時間、深さ上限で、先後を入れ替えて対戦する。`--baseline` を省くと初期重みの同じNNが比較相手になる。

```sh
python3 -m koushougi.evaluate_value work/training/model-02.json \
  --baseline work/training/model-01.json --pairs 4 --seconds 10 --depth 5
```

勝ち・負け・手数上限・合法手なしを個別に数える。未完了の対局を勝ちや引き分けへ換算しない。採用判断には、完了対局の勝敗と特殊ルールを含む局面テストを使う。

## 初期状態と学習処理の検証

```sh
.venv/bin/python -m unittest discover -s tests -v
```

全駒種、成り状態、段、先後について、初期NNの出力と従来評価の一致を検証する。同じ深さまで読み切った探索の最善手、PyTorchと対局用推論の出力、モデル保存と読込、自己対戦から学習・評価・追加学習までの経路も検証する。

DQNは、手番の符号反転、学習用NNによる行動選択と目標値用NNによる評価の分離、終局報酬、打ち切り後の予測、合法手なしの除外、目標値用NNの同期を検証する。保存後に中断して再開した計算と、連続実行した計算がCPUで同じ重み・経験・乱数状態になることも確認する。

## 線形評価AIによる過去の実験記録

### 第2世代

第2世代を採用した。第1世代との再検証では39勝1敗、20組中19組で勝ち越し、40局すべてで勝敗がついた。採用条件は20組中15組以上の勝ち越しと、40局中30局以上の勝敗確定。

### 第3世代の採用判定

第3世代は第2世代同士の自己対戦20局から7,810局面を得て学習した。第2世代との比較は25勝15敗で、20組中9組で勝ち越し、4組で負け越し、7組で同数だった。40局すべてで勝敗がついた。勝ち越し組数が採用条件の15組に届かなかったため、比較相手は第2世代を継続する。

### 第4世代の採用判定

第2世代同士の自己対戦60局すべてで勝敗がつき、25,395局面を保存した。第4世代は第2世代に4勝36敗で、組ごとの結果は0勝ち越し、16負け越し、4同数だった。騎総と仏狼機の修正後のエンジンを生成・対戦に使用した。

第2世代の重み80%と第4世代の重み20%を混ぜた候補は、別の乱数による40局で20勝20敗だった。組ごとの結果は6勝ち越し、6負け越し、8同数。両候補とも採用条件に届かなかったため、第2世代を継続する。
